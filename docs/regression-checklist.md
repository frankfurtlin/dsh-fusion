# 回归测试清单（真机，手机桥驱动）

每次发版后按这份清单跑一遍，约 20–30 分钟。目标是**用可重复的操作覆盖主链路**，
并把结果落到 `docs/regression-<日期>.md`。

## 0. 前置

1. 手机装好待测版本（`设置 → 关于` 记录 `versionName`）。
2. App 内「设置 → 能力 → 手机桥」已连接：服务器地址填 `https://dsh.frankfurtlin.top`，
   网关令牌用「网关登录」获取，点「连接手机桥」。
3. agent 侧确认：`phone_list` 返回 1 台在线；`phone_a11y_status` 为 `service=true, allowed=true`。
4. 记录基线：`phone_device_status`（屏幕尺寸/网络/电量）、当前主机（抽屉底部 chip）。

> 注意：手机桥常驻进程与 App 同命。**不要 force-stop App**，否则测试通道一起断；
> 冷启动只在「用户刚安装完」时顺手记录一次。

## 1. 启动与恢复

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1.1 | App 切后台 30 s 后回来 | 会话仍在、无重新登录弹窗 |
| 1.2 | 设置 → 诊断 → 性能 | `boot` ≤ 200 ms、`first_page` ≤ 500 ms |
| 1.3 | 观察抽屉底部主机状态 | 与「会话能否正常加载」一致（不能一边显示「登录…」一边正常用 → 见缺陷 P1） |

## 2. 会话列表

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 2.1 | 打开抽屉 | 列表出现；分组（今天/昨天/已归档）正确 |
| 2.2 | 依次点「全部/运行中/待确认/未读」 | 每个筛选的空态文案准确；点回「全部」恢复 |
| 2.3 | 搜索框输入关键词（如「插件」） | 命中高亮、显示工作区与时间、含已归档 |
| 2.4 | 清空搜索 | 回到会话列表，不残留 |
| 2.5 | 读性能账本 `session_list` | 中位数 ≤ 1 s（当前基线 3.8 s，待优化 P3） |

## 3. 会话页

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 3.1 | 打开一个会话 | 时间线渲染；思考/运行卡片可展开折叠 |
| 3.2 | 打开一个「生成中」的会话 | 流式内容持续更新；底部有「生成中·可直接插话」与停止按钮 |
| 3.3 | 点「请求失败，正在重试」横幅 | 展开显示原因；重试计数递增 |
| 3.4 | 点「+」 | 面板含 相册/拍照/文件/语音通话 + 权限/计划模式 |
| 3.5 | 点上下文百分比 | 用量面板：上下文占比、分项、累计输入/输出/缓存命中/轮数 |
| 3.6 | 面板 → 权限 | 四档 + 当前档位打勾 + 默认值说明 |
| 3.7 | 点会话标题 | 对话详情页（工作区、模型等） |
| 3.8 | 点「智能体团队」「语音通话」 | 面板/页面能打开，不白屏 |
| 3.9 | 读性能账本 `session_open` | ≤ 2 s（当前基线 1.3–8.9 s，待优化 P3） |

## 4. 设置各分组（逐屏截图）

概览卡 → AI（兴趣推送/模型/权限/个性化）→ 能力（手机操控/手机桥/联网搜索/图像与视频/插件）
→ 外观（主题/字号/收起过程/宠物）→ 通用（界面/语言/通知/语音/性能/后台/系统权限/隐私）
→ 主机（本机引擎/远程主机/引擎参数）→ 帮助与关于（使用帮助/社区/诊断/关于）。

通过标准：每个分组都能滚到底、没有空白卡片（历史事故：`SettingsTile` 漏 title 在 release
里渲染成灰块）、行尾值与实际状态一致。

另做一次**设置搜索**：搜「性能」「诊断」，结果要带完整路径并能直达。

## 5. 远程主机

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 5.1 | 抽屉 → 主机 chip → 连接电脑或服务器 | 远程主机页结构完整 |
| 5.2 | 查看当前主机卡与主机行 | 状态文案与实际一致（P1 缺陷点） |
| 5.3 | 添加网页登录（不保存） | 表单校验：地址归一化、缺密码提示 |
| 5.4 | 添加 SSH 主机（不保存） | 表单分组完整、测试连接按钮可用 |
| 5.5 | 精简历史开关 | 可切换，说明文字与生效条件正确 |

## 6. 兴趣推送 / 推送历史

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 6.1 | 设置 → AI → 兴趣推送 | 开关、条目列表、刷新/历史按钮齐全 |
| 6.2 | 点右上角历史 | 批次列表（时间 · 条数 · 标题预览） |
| 6.3 | 展开某一批 | 懒加载出该批全部条目（来源/标签/日期） |
| 6.4 | 断网后打开历史 | 显示错误态 + 重试，不白屏 |

## 7. 诊断与更新

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 7.1 | 设置 → 诊断 | 运行环境/连接/性能三段可读；错误原文可见 |
| 7.2 | 复制性能文本 | 剪贴板拿到完整账本（`phone_clipboard_get` 校验） |
| 7.3 | 设置 → 关于 | 版本号与 `pubspec.yaml` 一致 |
| 7.4 | 检查更新（不超过 24 h 节流） | 有新版本时给出更新入口 |

## 8. 无障碍抽查（读屏质量）

用 `phone_ui_tree` 抽查 5 个节点：

- 工具卡片 desc 是否被整段命令/输出撑爆（当前缺陷 P5，单节点可 > 8 KB）；
- 图标按钮是否都有 `desc`（返回/刷新/历史/设置）；
- 列表行是否给出「主标题 + 状态」而不是只有图标；
- 空态是否可朗读；
- 点击目标是否 ≥ 44 dp。

## 9. 结果记录

1. 截图存 `docs/regression-<日期>/NN-<用例>.jpg`（手机桥 `phone_screenshot` 的附件可直接拷）。
2. 报告用 `docs/regression-2026-11-26.md` 作模板：覆盖矩阵 → 问题清单（P1/P2…）→ 性能数据 → 未覆盖项。
3. 性能基线（1.1.10 实测，供比对）：

```
boot              77 ms
first_page       337 ms
session_list     269–8283 ms（中位 ~3.8 s，189 行）
session_open     1320–8938 ms（352–593 条记录）
```

4. 每个缺陷给出：现象 / 证据图 / 代码位置 / 成因假设 / 修复建议 / 优先级。
